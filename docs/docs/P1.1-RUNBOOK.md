1. First full run (owner machine, part of the delivery)
The first complete npm run ci runs on the owner machine, on Node 24.21.0, and its raw log is committed. Without the lockfile and the log, P1.1 is not delivered.

Check the toolchain and record it:
node -vnpm -vmkdir -p docs/evidence{ node -v; npm -v; uname -a; } > docs/evidence/p1.1-env.txt
Generate the lockfile without running any script, then install from it:
npm install --package-lock-only --ignore-scriptsnpm ci --ignore-scriptsnpm ls vite typescript >> docs/evidence/p1.1-env.txt
Run the full pipeline and keep the raw output (bash):
SITE_ENV=preview npm run ci 2>&1 | tee docs/evidence/p1.1-first-ci.log
PowerShell 7 (UTF-8 output):

New-Item -ItemType Directory -Force docs/evidence | Out-Null $env:SITE_ENV = 'preview'npm run ci 2>&1 | Tee-Object -FilePath docs/evidence/p1.1-first-ci.log"exit=$LASTEXITCODE" | Add-Content docs/evidence/p1.1-first-ci.logRemove-Item Env:SITE_ENV
Prove the SITE_ENV guard (record each result in the log):
npm run build                                    # must fail: SITE_ENV is requiredSITE_ENV=production npm run build:preview        # must fail: does not matchnpm run build:preview                            # must passnpm run build:production                         # must pass

3. Decisions and known limits
The ESLint network rules are a first-line guard only. The authoritative no-egress check is the Playwright test plus the CSP and Service Worker checks, official item P1.3.
parse5 is reserved for the P1.3 auditors and is not imported in P1.1.
.astro files are not measured by coverage. This is resolved in P1.4.
Coverage globs for scripts, src/lib and src/data/manifest match no files yet. Only src/config/site-env.ts is measured today, and each threshold binds to a file as soon as it appears. passWithNoTests is false.
tsconfig.scripts.json lists tests/**/*.ts and vitest.config.ts, which exist, so TS18003 cannot occur even though scripts/ is empty. Checked with tsc 6.0.3: the error appears only when no include glob matches any file.
SITE_ENV: npm scripts are checked through npm_lifecycle_event. The argv check stays as a safety net for direct calls such as npx astro build.
Owner settings on GitHub: require the check PR / verify, and protect .github/workflows/** with a ruleset or CODEOWNERS entry that requires owner review, with no bypass.
